01

CSS Modules & how class names map

BugConcept

What happened

We wrote styles.title.white and got undefined. The stylesheet had .title_white and a compound .title.gold, and none of it colored the words the way we expected.

Why

A CSS Module import is a flat object of strings — one key per class name, each value a uniquely-hashed class name. So:

  • styles.title is a string; therefore styles.title.white reads a .white property off a string → undefined.
  • A class named title_white becomes the key styles.title_white — the underscore is part of one identifier.
  • A compound selector .title.gold matches only an element carrying both classes. CSS Modules makes two keys, styles.title and styles.gold; the rule fires only if both are present.
The mental model — CSS in, object out
You write (.module.css)
.gold { color: gold }
→
Import gives you
styles = { gold: "SearchBox_gold__x7f2" }
→
You use
className={styles.gold}

Solution

Prefer single-purpose classes over compound selectors:

/* .module.css */
.white { color: white; }
.gold  { color: var(--color-accent); }
<span className={styles.white}>SPOT</span>
<span className={styles.gold}>CHECK</span>

How to study

In a scratch component, console.log(styles) and read the real object. Then prove to yourself: (a) what key a hyphenated class name becomes, and (b) that a compound selector needs both class strings in className.

02

next/font variable fonts: define once

Concept

What happened

We needed Archivo Black across several components without repeating archivo_black.variable on every element.

Why

The font is configured with variable: "--font-archivo-black". That gives you a CSS custom property, not a ready-made font. Two moving parts:

  1. archivo_black.variable is a class that defines the CSS variable on the element it's placed on (and its descendants).
  2. You consume it in CSS with font-family: var(--font-archivo-black).
.className applies the font directly to one element. variable only exposes the CSS variable — so you decide from CSS where it applies. Define it high, use it anywhere.

Solution

// layout.tsx — define the variable once at the root
<body className={archivo_black.variable}>{children}</body>
/* any .module.css — consume it anywhere below */
.white { font-family: var(--font-archivo-black); }

How to study

Temporarily remove the variable class from <body> and watch every var(--font-archivo-black) fall back to the default font. That proves exactly where the variable is defined.

  • MDN — Using CSS custom properties
03

The OKLCH color model

Concept

What happened

We needed to read and tweak colors like oklch(0.32 0.02 260) and produce a "light grey."

Why — the mental model

oklch(L C H) has three channels. Every bar below is a live OKLCH gradient sweeping one channel:

Sweep each channel
L — Lightness · 0 → 1 · dark → light
C — Chroma · 0 grey → vivid
H — Hue · 0–360° · red · yellow · green · blue · red

So oklch(0.32 0.02 260) = dark (L 0.32), nearly grey (C 0.02), faint blue (H 260) → a dark blue-grey. A light grey is high L, tiny C: oklch(0.7 0.02 260).

The app's actual tokens, rendered live

How to study

Take one token and sweep each channel independently: change only L, then only C, then only H, and name what moved. That isolates what each letter does.

  • oklch.com — interactive OKLCH picker
04

Design tokens

BugConcept

What happened

The same gold oklch(0.78 0.19 85) was hand-typed across four CSS files. Changing the brand color meant hunting every file.

Why

A token is a named value defined once and referenced everywhere. :root is the top of the document, so variables declared there reach every component's CSS. Change the definition once → everything updates.

Solution

/* globals.css */
:root {
  --color-accent: oklch(0.78 0.19 85);      /* gold — brand accent */
  --color-bg-nav: oklch(0.21 0.014 260);
  --color-border: oklch(0.32 0.02 260);
  --color-text-muted: oklch(0.7 0.02 260);
  --color-text: white;
}
.gold { color: var(--color-accent); }
Name by role, not appearance. --color-accent beats --color-gold — if the color later changes to orange, the name still tells the truth.

How to study — the verify trick

Flip --color-accent to an obvious red, save, and confirm every element using it moves together. If one doesn't, it's still hardcoded. Then revert. (This whole page uses that exact pattern — its palette is a token set.)

05

border-radius & the pill

Concept

Why percentage fails, and px wins

A percentage border-radius is relative to the element's own size, so a wide/short box becomes a stretched ellipse that shifts as it resizes. A large fixed px value (9999px) clamps to a perfect half-circle on each end at any height.

Both are live — same markup, different radius

Solution

.pill {
  border-radius: 9999px;
  padding: 10px 20px;  /* height + room so the curve has space */
}

A pill needs height and horizontal padding — the curve needs room, and content must stay off the rounded ends.

How to study

Build one box; try border-radius: 50% then 9999px at several widths. Watch when it becomes an ellipse vs a clean pill.

  • MDN — border-radius (percentage vs length)
06

Which element owns what — the input saga

BugBugConcept

Five separate symptoms, one theme: a CSS property lives on a specific element, and native inputs ship with their own defaults.

a) The input "turns blue when clicked"

Why: the <input> had no className, so none of the .input CSS reached it — what showed was the browser's default input with its native focus ring.

<input className={styles.input} />   {/* nothing worked until this */}
Debugging lesson: if styles "aren't applying," first confirm the class is actually on the element (inspect the DOM) before touching the CSS.

b) Removing the focus outline — accessibly

The ring is the input's default focus outline, targeted by :focus. Never remove it with nothing in its place — keyboard users rely on it. Prefer :focus-visible (keyboard focus, not mouse clicks) plus a custom style.

.input:focus-visible { outline: 2px solid var(--color-accent); }

c–e) Caret invisible · caret in the corner · input won't fill

SymptomWhyFix
Caret invisibleCaret defaults to text color — dark on darkcaret-color: var(--color-text)
Caret inside the rounded cornerContent starts at the pill's edge, in the curvehorizontal padding on the wrapper
Input won't fill the pillNative input has a fixed default widthflex: 1 on the input
The finished pill — click it, type, then Tab to it for the keyboard ring

How to study

Rebuild a bare <input> and add each rule one at a time — class → background → outline → caret → padding → flex — naming what each fixed. Change one thing at a time.

  • MDN — caret-color
07

CSS needs units (and the last-property trap)

Bug

What happened

padding: 10 16px; silently applied no top/bottom spacing.

Why

Any non-zero CSS length requires a unit. 10 (unitless) is invalid, so the browser discards the entire padding declaration. Related: a missing semicolon on the last property "works" until you add a line after it — which then gets swallowed.

padding: 10px 16px;   /* both values need units; end with ; */
Invalid CSS fails silently. DevTools shows the struck-through declaration — train your eye to spot it.
  • MDN — CSS values and units

10

var() does NOT work in SVG attributes

BugGotcha

What happened

<Search color="var(--color-text-muted)" /> didn't apply the color.

Why

lucide's color prop becomes an SVG attribute (stroke="var(...)"). CSS custom properties resolve only inside CSS property values, never inside raw XML/SVG presentation attributes — so the attribute stays an unresolved literal.

Solution

Let the icon use its default currentColor and drive it from CSS:

<Search className={styles.icon} />
.icon { color: var(--color-text-muted); }  /* stroke = currentColor inherits this */
Remember it as one line: "var() lives in CSS, not in attributes." This bites with any SVG library.

  • MDN — currentColor
11

React props: pass, receive, render, type

BugConcept

What happened

<button>name</button> rendered the literal text "name".

Why

Bare text in JSX is a string. To evaluate JavaScript, wrap it in braces: {name}. The full loop:

Pass (parent)
<Button name="Add Spot" />
→
Receive (child)
function Button({ name }: ButtonProps)
→
Render
<button>{name}</button>

Typing (because it's .tsx)

Untyped props are implicitly any. Describe the shape — a required prop makes TypeScript warn if a caller forgets it:

type ButtonProps = { name: string };
function Button({ name }: ButtonProps) { ... }

How to study

Build a tiny component that takes two props and renders both. Deliberately (a) forget the braces, (b) forget the type, and read each error.

  • React — JavaScript in JSX with curly braces
12

Layout: shrink-to-fit & push-right

Concept

a) A <div> stretches full width

A <div> is block-level — it fills 100% of its parent regardless of content. To hug the content: width: fit-content or display: inline-block. (Also ask whether the wrapper is even needed — a <button> is already content-sized.)

b) Push the Add Spot button to the far right

Horizontal position is decided by the parent's layout, not the element. Three flex tools: margin-left: auto on the last item, justify-content: flex-end on the parent, or space-between. We chose grouping — wrap the left items so the nav has two children, then space-between splits them, keeping the reusable <Button> free of nav-specific positioning.

A

Cross-cutting debugging principles

  1. "Styles not applying?" Check the class is on the element first, before editing CSS. (Ch 06)
  2. Change one thing at a time so you know what fixed it.
  3. Invalid CSS is dropped silently — DevTools shows the struck-through rule. (Ch 07)
  4. Know which element owns a property — background, text color, caret, focus each live somewhere specific. (Ch 06)
  5. var() is CSS-only — never in SVG/HTML attributes. (Ch 10)
  6. Name things by role, not appearance — tokens, and ideally class names too. (Ch 04)
B

Self-test

Answer aloud before opening each — explaining the "why" is what makes it stick.

Why is styles.title.white always undefined?
A CSS Module is a flat object of strings. styles.title is a string, so .white on it is a non-existent property → undefined. The class title_white would be the key styles.title_white.
What does the variable font option give you, and where must its class be applied?
A CSS custom property (--font-archivo-black), not an applied font. Its class must sit on an ancestor (e.g. <body>) so descendants can var() it.
In oklch(0.7 0.02 260), which number makes it lighter? Which makes it greyer?
The first (L = 0.7) controls lightness; raise it for lighter. The second (C = 0.02) is chroma; lower it toward 0 for greyer.
Why did the input show a blue ring even though .input:focus { outline: none } existed?
The <input> had no className, so the rule never reached it. You were seeing the browser's default focus ring.
Why did padding: 10 16px do nothing?
The 10 has no unit. An invalid non-zero length voids the whole declaration, so no padding applied.
Difference between padding and gap?
padding is space inside an element's edges; gap is space between flex/grid children.
Why didn't color="var(--color-text-muted)" work on the lucide icon?
It became an SVG stroke attribute. var() only resolves in CSS property values, not in presentation attributes. Use currentColor + a CSS color rule.
Three ways to push one flex item to the far right — and why is grouping cleanest here?
margin-left:auto, justify-content:flex-end, or space-between. Grouping keeps the reusable <Button> free of nav-specific positioning.
Why name a token --color-accent instead of --color-gold?
Role names survive redesigns — if gold becomes orange, --color-accent still reads true; --color-gold would lie.
